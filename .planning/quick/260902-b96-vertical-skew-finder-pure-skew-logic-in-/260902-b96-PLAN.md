  <action>
Create `src/morai/analytics/__init__.py` with a one-line docstring naming the package
(the `src/morai/money/__init__.py` precedent), and `src/morai/analytics/skew.py`.

`skew.py` is pure: no session, no clock, no network, no import of `morai.vendor` and no
import of `schwab`. `from __future__ import annotations` at the top, matching every other
module in `src/morai/`.

Public surface, exactly these three names:

- `class SkewMetric(BaseModel)` — `value: Decimal | None` and `reason: str | None`.
  Exactly one of the two is set. The reason is prose written for a human reading the CLI
  output, and when a bracket is missing it names the observed |delta| range on that side,
  so the reader can see how far off the chain was.
- `class SkewSnapshot(BaseModel)` — `expiry: date`, `underlying_price: Decimal | None`,
  and seven `SkewMetric` fields: `atm_put_iv_pct`, `put_iv_25_pct`, `call_iv_25_pct`,
  `rr_25_pct`, `put_iv_10_pct`, `call_iv_10_pct`, `rr_10_pct`.
- `def compute_skew(payload: JsonValue, *, expiry: date) -> SkewSnapshot`.

**The `_pct` suffix is load-bearing, not decoration.** Schwab sends `volatility` as a
percent (18.5 meaning 18.5%). This module keeps the vendor's own unit and performs no
conversion, so there is no scale to get backwards — and `NN-8` requires the unit to live
in the name rather than be inferred. Every IV-bearing field and local carries the suffix.

Private helpers:

- `_DECIMAL: TypeAdapter[Decimal]` at module level and `_parse_decimal(raw: JsonValue |
  None) -> Decimal | None`, copied from `reconciliation.py`'s pair. This is the third
  copy of that idiom in the codebase; `connections.py`'s own docstring already records
  the convention that a fourth copy is the signal to promote it into a shared helper.
  Say so in a comment here rather than promoting it now.
- Pydantic models for the payload *structure* only: the expiry maps as
  `dict[str, dict[str, list[ChainContract]]]`, and `ChainContract` carrying
  `strikePrice`, `volatility` and `delta` as `JsonValue` fields with `None` defaults.
  Typing those three as `Decimal` would make one illiquid `"NaN"` strike fail validation
  for the *whole chain*, which is the opposite of the required behavior — the structure
  parses strictly, the per-strike numbers degrade honestly through `_parse_decimal`.
  Extra keys are ignored; the payload carries dozens this module does not read.
- `_interpolate_iv_pct(points: list[tuple[Decimal, Decimal]], target_abs_delta: Decimal,
  side: str) -> SkewMetric` — `points` are `(abs_delta, iv_pct)` pairs.

`compute_skew` does this and nothing more:

1. `model_validate` the payload at the boundary. A structurally-wrong payload raises
   `ValidationError` and that propagates — a wrong symbol or a vendor error body is a
   loud failure, not a quiet all-`None` snapshot.
2. Select the expiry. Map keys are `"YYYY-MM-DD:DTE"`; match on the part before the
   first `:` against `expiry.isoformat()`. If the expiry matches in neither map, raise
   `ValueError` whose message lists the available expiry dates, sorted and deduped —
   that is a user typo and deserves to be loud. If it matches in one map but not the
   other, that side's metrics are `None` with a reason; do not raise.
3. Build each side's points. For every contract under the matched key, run `strikePrice`,
   `volatility` and `delta` through `_parse_decimal`; drop the contract unless all three
   come back non-`None`. Take `abs()` of the parsed delta — puts arrive signed negative,
   and the target is expressed as a magnitude. Sort by `abs_delta` ascending.
4. `_interpolate_iv_pct` for targets `Decimal("0.25")` and `Decimal("0.10")` on each
   side. Scan adjacent sorted pairs for the first `lo_d <= target <= hi_d`. Weight is
   `(target - lo_d) / (hi_d - lo_d)`; when `hi_d == lo_d` return `lo_iv` rather than
   dividing. An exact hit falls out of the same arithmetic with weight zero, returning
   `lo_iv` unchanged — one code path, no special case to keep in sync. When no adjacent
   pair straddles the target, return a `SkewMetric` with `value=None` and a reason
   naming the side, the target, and the observed |delta| range. **Never extend the line
   past the last point.** Do not quantize the result — the caller formats for display.
5. `rr_25_pct = put_iv_25_pct - call_iv_25_pct` when both values are present; otherwise
   `value=None` with a reason naming which side was unavailable. Same for `rr_10_pct`.
6. ATM: the put-side contract whose strike is nearest `underlyingPrice`, among those
   whose IV parsed. This system trades puts, so the put chain is the honest default —
   state that in the docstring rather than averaging the two sides, which would fabricate
   a number neither chain reported. Ties on distance resolve to the lower strike, a
   deterministic tiebreaker matching the `WR-02` precedent from Phase 9. When
   `underlyingPrice` is missing or unparseable, `value=None` with a reason.

Deliberately not built: `bid`/`ask`/`mark` are parsed by nothing and reported by nothing.
The requested outputs are the RR pair, the wing pair and ATM IV; a liquidity or spread
filter can read them when something actually asks for one.

`argparse` from the stdlib: `--symbol` (required), `--expiry` (required, parsed with

The flow, in order:

1. Open a session on the superuser engine, exactly as `create_admin.py` does. This is an
   operator tool, so it bypasses RLS by design; `schwab_client_for_user` carries no
   non-superuser guard of its own.
2. Resolve the user. With `--username`, select that user's id and confirm a
   `SchwabConnection` row exists for it. Without it, select the `user_id`s from
   `schwab_connections`: exactly one row means use it; zero rows exits non-zero saying no
   Schwab connection exists; more than one exits non-zero telling the operator to pass
   `--username`, and does not guess.
3. `auth = SchwabAuthAdapter(get_settings().schwab_credentials)`.
4. `async with schwab_client_for_user(session, user_id, auth) as client:` and inside it,
   one call: `await client.get_option_chain(symbol)`. `get_option_chain` takes a symbol
   and nothing else — fetch the whole chain and let `compute_skew` filter to the expiry.

   `read_first`.

   Print the message, never the payload and never a traceback.

Never print a token, a DSN, a password or the raw chain payload (`NN-34`).
