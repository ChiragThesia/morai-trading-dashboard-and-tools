**Pure `compute_skew()` deriving the 25-delta risk reversal, its 10-delta wing pair, and put-side ATM IV from a Schwab option-chain payload, plus a thin `tools/skew.py` CLI that fetches one live chain and prints it.**

## Accomplishments

- `src/morai/analytics/skew.py`: `compute_skew(payload: JsonValue, *, expiry: date) -> SkewSnapshot` — exact-hit strikes return their own IV unmodified, gaps interpolate linearly, `"NaN"`/`"Infinity"` strikes are dropped (never zeroed), a missing bracket returns `None` with a reason naming the observed `|delta|` range, and every number is a `Decimal`.
- `tests/analytics/test_skew.py`: five pure tests, no database, no vendor call — exact hit, interpolation, NaN/Infinity defence, no-extrapolation, and the vendor's percent unit surviving end to end.
- `tools/skew.py`: an operator CLI — superuser session (RLS bypass by design, matching `create_admin.py`), resolves the target user from `--username` or the sole `schwab_connections` row, fetches the chain through `schwab_client_for_user`, commits (so a mid-call token refresh is not lost), then hands the payload to `compute_skew`.

## Decisions Made

- **[Rule 1 — bug fix during Task 1]** `_interpolate_iv_pct` originally scanned only adjacent `(abs_delta, iv_pct)` pairs for a bracket containing the target, with an exact hit expected to fall out of that same arithmetic at weight zero or one. That works when at least two points exist, but the unit-survival test (`test_iv_stays_in_the_vendors_own_percent_unit_end_to_end`) feeds exactly one point per side, sitting exactly on the 0.25 target — with no second point to form a pair, the pair-scan loop never runs, and the function returned `None` with a bracket-not-found reason instead of the point's own IV. Fixed by checking every point for an exact `abs_delta` match *before* the pair scan, so a single-point exact hit resolves the same way a multi-point exact hit does. Observed failing (`assert None == Decimal('22')`) before the fix, green after. Committed as part of Task 1 (`16adff5`) since it was found and fixed inside that task's own red/green cycle, not a separate deviation after the fact.

No other deviations. Both tasks matched the plan's design as written, including the "one code path, no special case" interpolation shape (adjusted only for the single-point edge case above) and the exact `read_first` precedents (`reconciliation.py`'s `_parse_decimal`, `create_admin.py`'s superuser-session pattern, `schwab_client_for_user`'s no-commit contract).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Single-point exact-hit interpolation returned None instead of the point's own IV**
- **Found during:** Task 1, first `uv run pytest` pass after writing `skew.py`
- **Issue:** `_interpolate_iv_pct` only checked for an exact match implicitly, via the adjacent-pair scan — a side with exactly one parseable strike (the unit-survival test's shape) has no pair to scan, so an exact hit fell through to the no-bracket path.
- **Fix:** Added an explicit exact-match pass over all points before the pair scan, so both single-point and multi-point exact hits return the point's IV unmodified via one shared check.
- **Files modified:** `src/morai/analytics/skew.py`
- **Verification:** All five tests pass; `test_iv_stays_in_the_vendors_own_percent_unit_end_to_end` specifically exercises the single-point case.
- **Committed in:** `16adff5` (Task 1's own commit — found and fixed within the same red/green cycle, before the task was considered done)
