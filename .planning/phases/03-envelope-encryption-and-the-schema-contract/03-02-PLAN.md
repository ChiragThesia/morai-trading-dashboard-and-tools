<objective>
Complete the four-table schema criterion 6 names. `positions`, `legs` and `events` land
with the same plaintext/ciphertext split, the same RLS shape and the same documented
column provenance as `fills`, and the netted-ROLL prohibition becomes a database `CHECK`
constraint that no later caller can route around.

Purpose: criterion 4 is the phase's single hardest correctness claim and the code class
that cost v1 -$319,850. Criterion 2's disambiguation query needs `positions` and `legs` to
join against, and plan 03-03's nonce invariant needs `events`' ciphertext columns to union
over.

Output: migration `0008`, the `Position`/`Leg`/`Event` ORM models, an `insert_events()`
write path that keeps a compound event's two amounts split, and the tests that prove the
constraint fires on the shape it exists to catch and stays quiet on the shape it does not.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any SQL caller → the events table | Includes callers that never run application code — a psql session, a future migration, a repair script. |
| app process → Postgres | Only ciphertext, nonces and the plaintext-by-design columns cross. |
| one user's session → another user's positions, legs and events | RLS is the only thing between them; there is no admin path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Tampering | A ROLL event stored with its two amounts netted into one | critical | mitigate | Named `CHECK` constraint at the data layer, proved by raw-SQL inserts on a connection that bypasses the application (ASVS 5.0 V2, business-logic invariant enforced below the application). |
| T-03-10 | Repudiation | The constraint claimed to catch more than it can | medium | mitigate | The migration text and the test module docstring both state the ceiling: presence only, never value. Semantic correctness is Phase 5's oracle. |
| T-03-11 | Information Disclosure | Nonce reused across the two amount columns of one ROLL row | high | mitigate | Two separate `encrypt_field` calls, each generating its own nonce; asserted distinct in Task 3 and queried across all columns in plan 03-03 (ASVS 5.0 V11.3.4). |
| T-03-12 | Elevation of Privilege | One user reading another's positions, legs or events | critical | mitigate | RLS `ENABLE` + `FORCE` + admin-free `user_isolation` policy on all three tables, verb-narrowed grants (ASVS 5.0 V8; D3-18). |
| T-03-13 | Information Disclosure | A plaintext netted cash-delta column added for SQL convenience | high | mitigate | D3-04 forbids it; the reconciliation sum happens in Python after decrypt. No such column is created and the migration says why. |
