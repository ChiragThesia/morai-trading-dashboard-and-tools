<objective>
Execute the two SQL queries criterion 2 names, against real Postgres, against real oracle
data, using only the plaintext-by-design columns — and seed that data through the same
write path Phase 5 will use.

Purpose: `CRYPT-05` makes prices and quantities `bytea`, and SQL cannot sum ciphertext. The
plaintext column set is therefore not documentation — it decides which queries stay in SQL
and which move into Python after decrypt, and it constrains Phases 5, 6 and 9. If either
query cannot be expressed against the chosen set, D3-02 is wrong and the schema must change
before it ships.

Output: an oracle seeding helper that routes every fill through `insert_fills()`, and a test
module executing both queries and asserting the resolutions the oracle documents.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SQL query text → the ciphertext columns | A query that reaches into ciphertext to answer a question the plaintext set cannot is a silent widening of the encryption boundary. |
| the plaintext-by-design set → Phases 5, 6 and 9 | Whatever this plan proves queryable is what those phases are allowed to assume. |
| test seeding → the fill table | Seeding through anything but the real write path would prove the wrong thing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-26 | Information Disclosure | A plaintext column added for query convenience, widening what a dump reveals | high | mitigate | The two queries run against the D3-02 set exactly as written; widening it requires revisiting D3-02, and this plan reports rather than decides (ASVS 5.0 V14.1.1). |
| T-03-27 | Information Disclosure | A SQL aggregate over money forcing a plaintext cash-delta column | high | mitigate | The window sum happens in Python after decrypt; the test asserts no money value passes through a SQL aggregate (D3-04). |
| T-03-28 | Tampering | A fill attributed to the wrong position when two calendars share a contract | high | mitigate | The order-anchor query is executed against the two real shared-front-leg calendars, and an unresolvable case is asserted to return null rather than a guess (`NN-11`, ASVS 5.0 V2). |
