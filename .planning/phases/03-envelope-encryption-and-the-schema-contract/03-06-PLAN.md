Move Phase 2's isolation proof off the probe table and onto the real trading tables, and
observe it green there, before plan 03-07 drops the probe. Widen it while it moves: the same
zero-rows and write-rejection guarantees now cover `user_data_keys`, `positions`, `legs`,

delete `AUTH-07`, Phase 2's hardest requirement. The order is the whole point.

`positions` instead of a probe, and zero remaining references to either probe table outside
`db/models.py` and the migrations that created them.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| one user's session → another user's trading data | RLS is the only thing between them, on every one of the five new tables. |
| admin session → any trading table | The admin has cross-user reach on `users` alone; every data table must refuse. |
| the isolation suite → the table it points at | A suite pointed at a dropped table proves nothing, and a suite pointed at nothing passes vacuously. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-31 | Elevation of Privilege | Phase 2's isolation proof silently deleted along with the probe table | critical | mitigate | The suite is repointed and observed green against real tables in this plan, and the drop is a separate, later, dependent plan (ASVS 5.0 V8). |
| T-03-32 | Elevation of Privilege | A new table shipped without an RLS policy | high | mitigate | The cross-tenant guard is parametrized across all five new tables, so a missing policy fails a test rather than passing silently. |
| T-03-33 | Elevation of Privilege | An admin clause copied onto a trading table from `users`' policy | critical | mitigate | A mechanical assertion that no policy on the five tables names the admin setting, replacing a review convention with a test. |
| T-03-34 | Information Disclosure | The gate route disclosing another user's position by returning 403 instead of 404 | medium | mitigate | The byte-identical-404 guards move across intact, comparing content and headers rather than parsed JSON (D2-08). |
