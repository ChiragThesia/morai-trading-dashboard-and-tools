<objective>
Discharge the obligation `src/morai/db/models.py` has carried in its own docstrings since
Phase 1: drop `gate_money_probe` and `gate_user_scoped_probe` with an explicit migration now
that real trading tables exist. Move the two proofs those tables carried onto the real
schema rather than losing them.

Purpose: the probe tables were permanent surface for the life of their phases and no longer.
Leaving them past the phase that was supposed to retire them breaks an instruction the code
itself states, and leaves two tables in the schema that no requirement justifies.

Output: migration `0009`, the two model classes removed, the `Decimal` round-trip proof
repointed at the encrypted fill path, and the unit-suffix gate extended to cover ciphertext
columns.
</objective>

  <name>Task 2: the unit suffix survives onto ciphertext columns</name>
  <files>tests/test_money_column_naming.py</files>
  <read_first>
    `tests/test_money_column_naming.py` in full — especially its vacuity guard, which asserts the
    walker found at least one column before asserting the list of offenders is empty. Dropping
    `gate_money_probe` may leave the schema with no `Numeric` columns at all, which would trip
    that guard and fail the test. That is the guard working, not a bug. D3-12, `NN-8`, `D-04`.
  </read_first>
  <behavior>
    - Every money-carrying column in the schema names its unit, whether its storage type is
      `Numeric` or `LargeBinary`.
    - The walker counts what it walked and fails when it walked nothing, so the check cannot
      pass vacuously after a table is dropped.
    - The existing synthetic negative control still catches an unsuffixed `Numeric` column, and a
      new synthetic negative control catches an unsuffixed ciphertext column.
    - A ciphertext or nonce column whose base name carries a unit passes — the suffix convention
      accounts for the ciphertext and nonce name endings.
  </behavior>
  <action>
    Extend the walker to cover `LargeBinary` columns as well as `Numeric` ones. A `bytea` column
    is not excused from naming its unit: the unit is a property of the value, not of its storage
    type (D3-12). Decide and document how the suffix is recognised on a ciphertext column name —
    the unit suffix precedes the ciphertext or nonce ending — and apply it consistently so a
    money column that drops its unit is caught while an identity column such as a wrapped key or
    a wrap nonce, which carries no unit at all, is not falsely reported. Enumerate the
    unit-exempt binary columns explicitly rather than pattern-matching around them, so adding a
    new binary column forces a deliberate decision.

    Replace the probe-specific assertion with one naming a real encrypted money column, and add a
    second synthetic negative control with an unsuffixed binary money column, mirroring the
    existing one exactly. The negative controls are what prove the check has teeth rather than
    that it happened to pass today.

    Keep the vacuity guard and widen its count to both column types.

    Natural red: run the file after Task 3's migration and model removal and take the tripped
    vacuity guard as the red — it fires for real, on its own, with nothing built to provoke it.
  </action>
