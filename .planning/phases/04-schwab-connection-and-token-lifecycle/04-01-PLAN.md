<objective>
One user, one complete OAuth handshake against a `Protocol` fake, an encrypted Schwab
token landed in Postgres, and that connection read back as healthy — every layer this
phase touches, wired end to end, on one path.

Purpose: the phase's real difficulty is not OAuth. It is making an untyped, synchronous-
callback vendor SDK behave inside an async, no-`Any` codebase without either suppressing
type errors everywhere or silently losing the token write. Both failure modes are
invisible in a plan that builds layers horizontally: a lost token write returns 200 and
looks like success. Proving the whole path first means an architectural dead end costs
one commit instead of ten.

Output: `schwab-py` pinned and locked, a local `typings/schwab/` stub package wired into
both checkers, `MORAI_SCHWAB_*` settings, migration `0010` landing `schwab_connections`
with RLS, the `SchwabClient`/`SchwabAuth` Protocols, the one adapter module that imports
the vendor, the connection write and read path, `POST /schwab/connect`,
`GET /schwab/callback`, `GET /schwab/connection`, and the two gate meta-tests that keep
the vendor boundary and the suppression budget honest.
</objective>

    **The token-write hazard, designed around rather than documented around.**
    `token_write_func` must be a plain `def`, never `async def`. Verified against the real
    1.5.1 wheel: `schwab/auth.py` calls the closure with no `await` anywhere in the file,
    even on the `asyncio=True` path. An `async def` closure returns a coroutine that is
    assigned, never awaited, and discarded — Python emits only a "coroutine was never
    awaited" RuntimeWarning at garbage collection, which a suite not treating warnings as
    errors swallows entirely, and OAuth appears to succeed while the token silently never
    persists. So: capture synchronously into a plain in-memory holder (a one-element list
    or a small mutable dataclass), let the vendor call return, then persist explicitly from
    the caller's own async code. Say so in a comment at the closure, naming the failure
    mode, so a later reader converting it to `async def` for consistency meets a warning
    rather than a silent data-loss bug. `client_from_received_url` is synchronous and makes
    a real network call, so the adapter awaits it through `asyncio.to_thread` rather than
    blocking the event loop.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /schwab/callback` | Unauthenticated, and the query string carries an authorization code that is bearer-equivalent. |
| Schwab → adapter | Untyped vendor JSON crosses here; `response.json()` is the untrusted-input boundary for the whole project. |
| app process → Postgres | Only ciphertext, nonces and plaintext-by-design connection metadata cross. No key does. |
| Postgres → a stolen dump | The dump must not yield a usable Schwab token without the KEK. |
| one user's session → another user's connection row | RLS is the only thing standing here. |
