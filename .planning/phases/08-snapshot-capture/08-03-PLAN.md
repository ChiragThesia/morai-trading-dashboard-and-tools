<objective>
ROADMAP criterion 4, made true: "The repair path is runnable and rebuilds marks from the raw
observations actually stored, and it ships in this phase alongside the writer rather than a phase
later."

That last clause is a direct citation of `L040`'s cost line and it is a hard ordering constraint, not
a preference. In v1, Phase 25 stopped `snapshot-calendars` writing gap and NaN rows and the actual
repair landed a full milestone later in Phase 40; every calendar affected in between carried silent,
unrecoverable holes. This plan therefore runs in wave 2, beside the gap-semantics work, not in a
trailing wave that could get cut.

Purpose: the raw layer `D8-01`/`D8-04` insist on is only worth its storage cost if something reads it
back. A parsed-fields-only store can rebuild only what was already parsed correctly, so a parsing bug
becomes as permanent as an outage. This plan is the thing that makes the raw layer real.

Output: `src/morai/ingest/snapshot_repair.py`, its Procrastinate task, `tools/repair_snapshots.py`,
and the honest-gap backfill for a slot the scheduler never fired.
</objective>

Define `StoredObservation`, a frozen dataclass carrying `leg_id: UUID`, `occ_symbol: str`,
`slot_time: datetime`, `observed_at: datetime`, `raw_payload: JsonValue | None` and
`gap_reason: SnapshotGapReason | None`. Define `RepairOutcome`, frozen, carrying
`observations_read: int`, `marks_written: int` and `gaps_by_reason: Mapping[str, int]`.

Define `read_snapshot_observations(session, user_id, *, since: datetime | None = None) ->
tuple[StoredObservation, ...]`. Join `snapshot_observations` to `legs` on `leg_id` so each row carries
its own `occ_symbol` — the repair needs it to rebuild the wire symbol the parser looks the payload up
by, and re-deriving it any other way would be a second source of truth. Filter on `slot_time` when
`since` is given. Add no explicit user predicate beyond the one already needed for the join; RLS is
the filter, the same convention `read_fills`, `read_connection` and `read_sync_runs` all state. For
each row with no gap reason, resolve its own `key_version` through `dek_for_version`, decrypt
`raw_ciphertext` under the AAD helper the writer used, and JSON-decode. For each row with a gap
reason, carry the reason through with a null payload. Order by `slot_time` then `leg_id` so two runs
are comparable element-wise.

Define `repair_snapshot_marks(session, user_id, *, since: datetime | None = None) -> RepairOutcome`.
Take this user's `pg_advisory_xact_lock` with the user id bound as a parameter as its first action,
mirroring `sync_user` and `capture_user_snapshot`, so a repair and a live capture for one user
serialise rather than interleave. Read the observations, and for each build the leg's wire symbol
through `to_schwab_wire_symbol` and call `parse_quote_payload` with the stored payload — the identical
pure function the live writer calls, so a repair can never derive a different mark from the same bytes
than the writer would have. Carry a gap observation straight through as a gap mark with its own stored
reason preserved, never rewritten to a generic one. Assemble `SnapshotWrite` values and hand them to
`write_snapshot_marks`, which applies the same asymmetric clause: a rebuilt real value heals a gap and
corrects an earlier real value, and a rebuilt gap can never replace a real mark. Do not commit — the
caller owns the transaction, the convention every write path here states. Return the counts.

Make the no-vendor-call property structural, not aspirational: import nothing from `morai.vendor` in
this module, and state in the docstring that the repair is a pure recompute over already-stored bytes
and that this is what `D8-04` bought. Test 4 asserts this by walking the module's AST for imports
rather than by trusting the comment.

Do not add any path that invents a mark for a leg and slot with no stored observation. The repair
rebuilds what was stored; the honest gap for a slot that was never captured at all is Task 3's job and
it writes a gap, never a value.
