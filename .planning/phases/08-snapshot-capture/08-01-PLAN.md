<objective>
Phase goal (ROADMAP, verbatim): "Every open position is repriced on the 30-minute RTH cadence from
day one, and a slot without data is recorded as a gap rather than invented."

This plan is the phase's tracer: the thinnest production-quality path through every layer the phase
touches. A real Procrastinate periodic tick, firing on a real RTH slot, fans out one capture job per
connected user; the drained job resolves that user's open legs from Phase 7's own derivation, builds
Schwab wire symbols, calls `get_quotes` once, parses the response, and lands one encrypted raw
observation and one encrypted mark per leg — through the asymmetric upsert, under RLS, on the
`morai_app` role.

Purpose: nothing in this system has ever called `get_quotes`, and nothing has ever written a
snapshot row. Every later plan in this phase — gap semantics, the repair path, the run ledger —
builds on top of this slice, so the slice is proven end to end on the first commit rather than after
ten. Phase 7's own code review found a feature built, tested, merged and unreachable because the
production call site never enabled it; this plan's verification runs through the genuine deferred
Procrastinate task, not a direct function call.

Output: migration 0015 (three tables, grants, RLS), three ORM models, the promoted data-key helper,
`src/morai/ingest/snapshots.py`, the worker wiring, and three test files.
</objective>

Add `snapshot_observations_gap_reason_check` restricting `gap_reason` to the four values `no_market_data`, `connection_expired`, `vendor_error`, `slot_not_captured`. Pin all four now even though only the first is written by this plan — `connection_expired` is `D8-14`, `vendor_error` is the orchestrator's resolved answer to research open question A3, and `slot_not_captured` is what plan 08-03 writes for a slot Procrastinate never fired at all; a later `ALTER` to widen a `CHECK` on a populated table is a migration this phase can spend one line avoiding. Add `snapshot_observations_leg_slot_key`, a unique constraint on `(leg_id, slot_time)` and nothing else: `leg_id` is a UUID that already functionally determines both `user_id` and `root` through the existing foreign-key chain, so neither adds discrimination (`NN-1`, Pitfall 4); keying on the OCC symbol instead would silently collide two positions that re-entered the same contract (`L001`/`L002`).
