<objective>
Phase goal (ROADMAP, verbatim): "Open/closed state, per-leg settlement, and rolled-position chains
are computed from events, with no second writer for anything derivable."

This plan closes ROADMAP criterion 4 end to end. `detect_roll` has shipped since Phase 5 as a
negative guard with no caller; this plan gives it one. A broker order that closes one expiry and
opens another at the same root, strike and option type derives a single ROLL event carrying both
amounts split, linked back to the position it rolled from — and the campaign view then returns a
real chain built from derived rows rather than hand-seeded ones.

Purpose: `D5-01` deferred positive ROLL derivation "to a phase that owns a real fixture for it,"
because building unvalidated money math for the failure that cost v1 $319,850 would reproduce the
exact conditions of that loss. `D7-09` resolves the deferral on one condition: the two halves are
priced by the *same* `_signed_leg_amount` and `_net_amount` the 13-calendar oracle already validates.
No new arithmetic is introduced. That is what answers `D5-01`'s objection instead of overriding it.

**The oracle is the gate.** Its global invariant — exactly 4 events per calendar, all OPEN or CLOSE,
never a spurious ROLL — is the single best regression signal in this phase. Order `1006797510202` is
a real order that spans two calendars and is *not* a roll; if this plan's positive path tags it as
one, the oracle goes red and that is a hard stop, never a fixture to update.

Output: the roll pass inside `derive_events`, and `tests/ledger/test_roll_derivation.py` with
synthetic, explicitly-labelled fixtures.
</objective>
