<objective>
Phase goal (ROADMAP, verbatim): "Open/closed state, per-leg settlement, and rolled-position chains
are computed from events, with no second writer for anything derivable."

This plan is the phase's tracer: the thinnest end-to-end slice through every layer the phase
touches. A real Procrastinate `sync_user` job pulls Schwab transactions, lands fills, **creates the
position and its legs**, and derives events — all inside the one session the worker already opens.

Purpose: `sync_events` has zero call sites under `src/` today, and nothing under `src/` has ever
created a `positions` or `legs` row (Pitfall 3, D7-12). Without this slice, every later plan in this
phase ships as dead code — Phase 8 reprices nothing, Phase 9 reconciles nothing.

Output: `src/morai/ledger/positions.py` (creation path + two write-token sentinels), the wiring in
`sync_user`, and three tests: an end-to-end worker assertion, a unit suite for leg-role assignment,
and the AST write-boundary gate.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Schwab vendor payload → `sync_user` | Untrusted vendor JSON crosses into the ledger; already narrowed by `extract_fills` and Pydantic validation upstream of this plan. |
| Worker process → Postgres | `sync_user_task` connects as `morai_app` (`NOSUPERUSER NOBYPASSRLS`) and asserts it cannot bypass RLS before touching a protected table (Phase 6). This plan adds two new write targets inside that same session. |
| Application code → `positions` / `legs` tables | The write-token sentinel is the boundary this plan erects. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Tampering | `create_positions` writing `positions`/`legs` | high | mitigate | The call runs on `sync_user`'s existing session, which sets `app.current_user_id` transaction-locally before any write, so RLS `user_isolation` evaluates on both new tables; `user_id` is denormalised onto `legs` so its policy needs no join. |
| T-07-02 | Tampering | A second, ungated writer into `positions`/`legs` | high | mitigate | `_POSITION_WRITE_TOKEN` / `_LEG_WRITE_TOKEN` on the constructors plus the AST gate in Task 3 (D7-14). |
| T-07-03 | Information Disclosure | `plan_positions` inputs | low | accept | Every field it reads (`occ_symbol`, `position_effect`, `order_id`) is already plaintext by design in migration 0008; no ciphertext is decrypted in this path. |
| T-07-04 | Denial of Service | `read_fills` whole-user read on every sync | low | accept | Already this codebase's stated ceiling for `sync_events`; correct and cheap at a handful of users, revisited only at a volume this project does not have. |
| T-07-05 | Elevation of Privilege | Worker session role | high | mitigate | Unchanged from Phase 6 — `sync_user_task` already calls `assert_connection_cannot_bypass_rls` before this plan's writes; this plan adds no new session and no new engine. |
| T-07-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed in this plan. `tzdata` is installed in 07-03 behind a blocking human checkpoint. |
</threat_model>
