<objective>
The cycle itself. One periodic tick fans out into one job per connected user; running the same
window again changes nothing; and a user connecting for the first time gets the full lookback
backfilled in chunks rather than the vendor's own narrow default.

Purpose: plan 06-01 proved one user's transaction lands. This plan proves the three properties that
make that safe to run unattended — that every connected user is covered and one user's broken token
cannot starve the rest, that the work is genuinely repeatable rather than merely not-yet-repeated,
and that a new connection's history reaches back past the moment of connection.

Output: the periodic fan-out task and its no-double-fire proof; the idempotency suite including the
WR-A3 assertion that the conflict clauses are safe for the reason claimed; and the first-connect
backfill proved window by window.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the scheduler → the set of tenants | The fan-out reads across every user by definition. It is the one cross-tenant read in the ingest path and needs its ceiling stated. |
| one user's job → another user's cycle | Procrastinate's job boundary is the isolation. Without it, one expired refresh token stops everyone. |
| a repeated window → stored rows | The conflict clauses decide whether a re-run is a no-op or a silent data loss, and the difference is whether the key is complete. |
| requested window → returned window | The vendor may honour less than was asked for, and a truncated window looks identical to an empty one. |
