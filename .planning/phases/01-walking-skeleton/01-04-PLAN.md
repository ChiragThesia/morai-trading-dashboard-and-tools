<objective>
Prove the gate has teeth. Deliberately-violating fixture files, and a meta-test that runs each
checker against them and asserts it fails with the rule code it is supposed to fail with.

Purpose: the failure mode worth catching is not a developer writing `Any` — it is somebody
loosening a config knob so that every gate silently stops firing and the build stays green. Research
measured this exact hazard live: `typeCheckingMode: "strict"` alone reports zero errors on a file
containing `Any`, and `reportAny`/`reportExplicitAny` must be named explicitly. `L058`'s own
prescription is to prove the guard works by injecting a violation and confirming the build fails
there. This is the same shape as the oracle's fourteenth synthetic negative control.

Output: `tests/gate/` as a first-class directory, plus the repo-hygiene guard that keeps a secret
and an iCloud duplicate out of a public repository.
</objective>

`tests/gate/test_type_gate.py` holds one parametrized test over `(fixture_path, tool_argv,

is precisely the vacuous-guard failure this test exists to prevent.

Write the test first and record the failing run (D-08). Make the red run real by pointing the
scanner at a temporary file containing an offending line before the exclusion logic exists.

D-06 defines a justified suppression as one that names its rule **and** carries a reason comment on
the same line. ruff's `PGH003` already forces the rule code; nothing forces the reason. This test
does.

Build the reason-marker token at runtime from its parts rather than writing it as a single literal
in the scanner's own source. Otherwise the scanner file contains the very string it searches for,
and either it must special-case itself or it reports itself — both are the self-invalidating shape
that makes a guard quietly stop meaning anything. Excluding the scanner's own path by name is the
second half of the same protection; do both.

Enumerate files with `git ls-files 'src/**/*.py' 'tests/**/*.py'` so untracked scratch files cannot
fail the build, and drop anything under the fixtures directory. Report every offending
`path:lineno` in the assertion message.

Explain the valve in the module docstring in one sentence: it exists for a genuinely wrong vendor
stub, and using it costs a reason visible in the diff. A gate with no escape hatch pushes the
pressure somewhere worse — an untyped `object` plus runtime asserts, with no comment saying so.
  </action>

bandaid — plan 01-01 extended `.gitignore`, and this test asserts nothing matching the pattern is
tracked. Verified in the phase context: the working tree currently holds zero collision artifacts,

Research finding 8: the repository is public. Assert `.env` and `.env.local` are untracked, that
`git log --all -- .env` returns nothing, and that no tracked text file carries a Postgres URL with
a password in its userinfo. Exclude `.env.example` and this test's own path from that scan, and
add a separate assertion that `.env.example` holds placeholders only. Enumerate with `git ls-files`
and skip anything the file command reports as binary.

assertion message. It is readable from `railway variables` at any time; the point of this test is
that it never needs to be written down. Match a shape, not a value.

Scope every scan to `git ls-files` output. Never scan the working tree at large, and never scan
