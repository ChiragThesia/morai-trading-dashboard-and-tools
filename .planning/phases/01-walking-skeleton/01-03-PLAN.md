<objective>
Make the unit of a money value impossible to lose. One conversion function that will not run
without being told the multiplier, and a test that walks the database metadata and fails any money
column that does not name its unit.

Purpose: this is `NN-8` typed. v1 stored `openNetDebit` in dollars, fed it to a formula expecting
index points, and displayed a +$395 trade as −$319,850. D-01's `NewType`s catch that in Python;
D-04's suffix rule catches it in SQL, where no Python type is in play — and the v1 bug lived in a
value read straight out of SQL.

Output: `points_to_usd`, its tests, and the metadata guard every later phase's tables inherit.

Reversibility: D-04 is rated **one-way** — renaming a money column after Phase 3 writes rows means
a migration against encrypted tables. Recorded, not gated: the user asked for an unattended run.
</objective>

    - The multiplier is positional-or-keyword and has no default; calling `points_to_usd(pts)` is a type error and a `TypeError` at runtime
    - Passing a `Usd` value where `IndexPoints` is expected fails the type checker (proven as a gate fixture in plan 01-04, asserted here only for the runtime path)
    - The returned value is re-wrapped as `Usd`, not left as a bare `Decimal`
    - The exact contract multiplier literal appears in exactly one file under `src/`
  </behavior>
  <action>
Write the tests first and record the failing run (D-08).

Add to `src/morai/money/units.py` (D-02): one function,
`def points_to_usd(pts: IndexPoints, multiplier: int) -> Usd`, returning
`Usd(Decimal(pts) * Decimal(multiplier))`. The multiplier is required. Never give it a default —
a default is how a caller stops thinking about which contract it is converting, which is exactly
the `NN-8` failure this exists to prevent. Name in the docstring the concrete v1 bug: `openNetDebit`
stored in dollars fed to a formula expecting index points, +$395 displayed as −$319,850, five
rounds of oracle-driven debugging.

Define the SPX contract multiplier as a single module-level named constant in this file and nowhere
else. Every call site passes the named constant, never a bare number.

The single-literal test enforces this with a repository grep scoped to `src/` only, excluding
`src/morai/money/units.py`: any word-boundary occurrence of the multiplier literal outside that one
file fails the test. Scope the grep to `src/` — never repository-wide — so plan prose, docs and
learnings entries that legitimately discuss the number cannot invalidate it.
