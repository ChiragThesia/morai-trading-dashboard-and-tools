no Docker, no CI. It is arithmetic, and it is the part that actually guards the ledger.

Write the test first and observe it fail (D-08) — start with a deliberately wrong expectation so
the red run is real.

Assert **bit-inexactness**, `Decimal(float(x)) != Decimal(x)`. Do not assert a visible digit flip.
RESEARCH.md measured this across 8 candidates and the orchestrator reproduced it independently:
`NUMERIC(14,4)` holds at most 14 significant digits, an IEEE-754 double carries about 15.95, so no
value both fits the column and visibly loses a digit at four decimal places. A test claiming
otherwise would be unprovable at this column width.

Put that reasoning in the module docstring and in the assertion messages, so a future reader hunting
for a value that "actually looks different when printed" finds the answer instead of the hunt.
State plainly that none exists inside this column's range.

Include `Decimal("7425.5000")` as an explicitly-labelled counter-example asserting it IS bit-exact
— an exact binary fraction, which as the canary would pass for the wrong reason.

`src/morai/money/units.py` (D-01): `Usd = NewType("Usd", Decimal)` and
`IndexPoints = NewType("IndexPoints", Decimal)`. Nothing else yet — plan 01-04 adds the conversion.
Arithmetic decays to plain `Decimal` by design; every result is explicitly re-wrapped, and that
noise is the point.

`src/morai/money/api_types.py` (R-02, measured): `def _parse_decimal_strict(v: object) -> Decimal`
returning `v` unchanged when already a `Decimal`, `Decimal(v)` when a `str`, and raising
`ValueError` naming the received type otherwise — so a JSON float and a JSON int are both rejected.
Export `StrictDecimalField = Annotated[Decimal, BeforeValidator(_parse_decimal_strict)]` and a
`UsdField` alias. This exists because FastAPI routes every request body through
`TypeAdapter.validate_python` on a pre-parsed dict, never `validate_json` — read directly from
FastAPI 0.141.1's source in RESEARCH.md R-02 — so a bare strict `Decimal` field would reject the
exact JSON-string format D-03 makes the API emit. Every money-carrying Pydantic field uses this
alias, never a bare `Decimal`, `Usd` or `IndexPoints`. Function signatures and non-Pydantic code
keep `Usd`/`IndexPoints` as D-01 specifies.
