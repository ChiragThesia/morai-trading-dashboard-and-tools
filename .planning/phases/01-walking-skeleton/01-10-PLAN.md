<objective>
Turn CI from a report into a gate. A branch ruleset on `main` that requires a pull request and
marks all four checks required, proven by a pull request GitHub actually refuses to merge.

Purpose: criterion 2 says a branch introducing `Any`, a `cast`, or an unjustified suppression
"cannot be merged". Red CI reports; a ruleset refuses. This is the only option that satisfies that
wording literally.

Why this plan runs last: creating the ruleset immediately stops direct pushes to `main`. Doing it
earlier would block this phase's own remaining commits mid-run, and this run is unattended.

Availability is settled, not assumed. Measured on 2026-08-30: the repository is **public**,
`repos/.../rulesets` returns an empty array rather than a 403, and the account is on the free plan.
GitHub gates rulesets on repository visibility, not on plan alone — public repos get them on every
plan; it is private repos on Free that lose the feature. The phase context's `R-03` risk assumed a
private repo and evaporated on that one fact. D-16 stands as written.
</objective>

Order matters here and getting it wrong strands an unattended run. Commit and push the
`.planning/config.json` change to `main` **first**, then create the ruleset. A ruleset created
first turns the very next push to `main` into a rejection.

Flip `.planning/config.json`'s `git.branching_strategy` from `none` to phase branches, so later
phases work on `gsd/phase-{phase}-{slug}` and land through pull requests. The
`phase_branch_template` key is already set to that shape. `/gsd-pr-branch` exists to keep
`.planning/` commits out of the pull request. Change that one key and nothing else in the file.

Confirm the ground before creating anything, rather than trusting the recorded measurement:
`gh api repos/ChiragThesia/morai-trading-dashboard-and-tools --jq '{visibility,private}'` and
`gh api repos/ChiragThesia/morai-trading-dashboard-and-tools/rulesets`. Visibility must be public
and the ruleset list must be empty. If either has changed, stop and report rather than working
around it.

Create one ruleset on `main` with `enforcement: active`, targeting the default branch, carrying two
rules: `pull_request`, so a direct push to `main` is refused, and `required_status_checks` naming
all four job names from plan 01-07's summary **verbatim**. Set the strict policy so a branch must
be current with `main` before it merges.

A mistyped check name silently gates nothing. The ruleset accepts a name no job produces and then
waits forever for a check that never arrives, which reads as pending rather than as an error. Read
the created ruleset back and compare the four strings character for character against
`.github/workflows/ci.yml`.

No required reviewers. This is a solo repository, and a review requirement nobody can satisfy is a
lock, not a gate.

This is criterion 2's proof, and it must be a refusal, not a red badge.

Branch from `main`. Commit two violations in one commit, mirroring plan 01-07's negative control: a
source file under `src/` annotating a parameter with the banned `Any` name, and one existing test's
assertion inverted. Push the branch and open a pull request with `gh pr create`.

Wait for the checks, then capture three things verbatim for the phase record:

  1. `gh pr checks <n>` output, showing the failing required checks by name.
  2. `gh pr view <n> --json mergeable,mergeStateStatus` — the merge state must report the pull
     request as blocked. This is the fact criterion 2 turns on. A red check that still allows a
     merge would mean the ruleset names a context no job produces.
  3. The output of an actual attempted merge: `gh pr merge <n> --squash`. It must be refused.
     Capture the exact refusal message. Attempting it is what distinguishes "GitHub says blocked"
     from "GitHub blocks", and the second is what the criterion claims.

Then also prove the direct-push half: from a local clone on `main`, attempt to push a trivial
commit directly and capture the rejection. Reset afterwards so nothing is left staged.

Close the pull request without merging and delete the branch. Nothing here merges and nothing here
is fixed — the refusal is the artifact.

Append all captured output to `01-RED-GREEN-EVIDENCE.md` under a criterion 2 heading. That file is
already tracked, so this lands through a pull request now that the ruleset is active — which is
itself the first exercise of the new workflow, and a useful one.
