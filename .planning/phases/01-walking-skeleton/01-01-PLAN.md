<objective>
Stand up the build: dependency pins, the strict type-gate configuration, the single gate script,
the configuration model, and the Alembic environment. Everything here runs with no database and no
Docker, which is what makes it the first thing built.

Purpose: every later plan and every later phase inherits these gates. Getting the type-gate config
wrong here silently disables OPS-01 everywhere — research measured that `typeCheckingMode:
"strict"` alone does NOT enable `reportAny`/`reportExplicitAny`.

Output: a repository that installs, type-checks, lints and tests on a pinned interpreter, with an
Alembic environment ready for the first migration.

**No local database in this phase.** Docker Desktop's daemon is broken on this machine (`docker
info` returns a 500 from the API socket), Railway's Postgres is private-network-only (`PGHOST` is
`.railway.internal`, unroutable from here), and `psql` is not installed. A Railway TCP proxy was
deliberately not created — widening the production database's attack surface to solve a local
tooling problem is the wrong trade. Every DB-backed test in this phase runs in CI (plan 01-02) or
on the deployed service (plan 01-08). Do not plan around, or attempt to repair, Docker.

Reversibility: D-18 (`src/` layout, uv, one installable package `morai`) is rated **costly** —
moving the package root later touches every import and both Railway start commands. Per the user's
explicit instruction this run is unattended, so no `checkpoint:decision` is emitted; the rating is
recorded so the weight survives in the record.
</objective>
