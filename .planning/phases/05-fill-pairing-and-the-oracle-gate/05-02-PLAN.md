<objective>
The two documented hard cases, each given its own attention: a front-month contract shared by
two calendars, and a position state column that cannot lie because it is never read.

Purpose: hard case 1 has two layers and the second is the one that actually reached production.
The disambiguation logic can be perfectly written and still fail if the read that feeds it was
narrowed to one calendar's own legs, because the anchor lives on the sibling's leg. Hard case 2
is criterion 2, and Phase 3 already answered it by never creating the column — this plan turns
that absence from a fact someone remembers into a fact the suite checks, structurally and
behaviourally.

Output: the shared-front-leg proof in both layers, the explicitly-unresolved negative case, the
cross-user isolation proof, the position-state mutation proof, the 14th synthetic fixture and
its seeding helper, and `detect_roll` as a real callable predicate with its negative case.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| one user's derivation → another user's positions | Two users can legitimately hold legs on the identical OCC contract; only `user_id` separates them. |
| broker-reported contract symbol → parsed strike and expiry | An untrusted string becomes the input to a roll decision. |
| stored position state → derived events | Must be a one-way street: state is an output, never an input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-02 | Information Disclosure | Resolution crossing two users who share an OCC contract | critical | mitigate | Task 1's cross-user test seeds `8a63aa81` for user A and `6303e6af` for user B — both carrying `SPXW260618P07275000` — and asserts no resolved position belongs to the other user. `RESOLVE_FILL_POSITIONS_SQL`'s `:user_id` predicate plus RLS `FORCE` are the two belts. |
| T-05-03 | Tampering | An ambiguous fill guessed into the wrong position | high | mitigate | Task 1's negative case: two positions sharing both legs leave every fill in their shared order explicitly unresolved with zero events (`NN-11`). |
| T-05-05 | Tampering | A stale or mutated position column steering classification | critical | mitigate | Task 2 rewrites `opened_at` and `closed_at` to a sentinel and re-derives from an emptied `events` table, asserting a byte-identical set; the AST gate from 05-01 is the structural half (D5-02, `NN-9`, `L022`). |
| T-05-06 | Tampering | A malformed contract symbol silently parsed into a wrong strike, turning two unrelated fills into a roll | high | mitigate | `parse_occ_symbol` raises `ValueError` naming the symbol rather than returning a partial result; `detect_roll` requires every part of the strict predicate and no positive ROLL path ships this phase (D5-01). |
| T-05-SC | Tampering | Supply chain: package installs | n/a | accept | This plan installs, upgrades and imports no external package. |
